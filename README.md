# 公交刷卡明细 · Parquet 分区布局试算

只做**试算**、不重写任何文件的网页工具：上传两张 CSV，在“全表文件数上限”预算内，
找出每个运营日应选择「仅按日分区」还是「日 + 线路分区」，使历史查询的总扫描代价最低。

## 1. 试算规则（与需求逐条对应）

1. 每个运营日只有两种候选布局：
   - **仅按日（day_only）**：当天数据只按日分区；
   - **日 + 线路（split）**：日分区下再按线路拆分。
2. 文件按**单文件行数上限**装满一份再开下一份：对每个 `(入仓批次, 线路)` 的行数
   独立做 `ceil(行数 / 上限)` 切分；**不跨批次拼文件**。
   - day_only 的文件数 = 各批次当天合计行数各自切分后求和；
   - split 的文件数 = 各 `(批次, 线路)` 切分后求和（因此可能多开小文件）。
3. 查询只按分区裁剪，**命中的文件整份计入扫描**，扫描行数按文件承载的全部行数计：
   - day_only：任何查询都扫当天全部文件、全部行数；
   - split + 指定线路：只扫该线路文件；
   - split + 线路留空（全线查询）：仍扫当天全部文件。
4. 查询成本 = 命中文件数 × 每次打开折合扫描行数 × 执行次数，按执行次数加权汇总。
5. 布局选择建模为 **0/1 背包**：每个运营日拆分布局的“重量 = 相对日布局多开的文件数”，
   “价值 = 全部覆盖查询因此节省的代价”，在 `文件数预算 − 最少文件数` 的容量内求最大节省。
   - 多开文件数为 0 且拆分有益的日子免费拆分；
   - 拆分反而增加代价的日子永远不拆；
   - **预算 < 最少文件数（全部仅按日）时，不返回布局，只报至少需要多少文件**。

## 2. 输入 CSV 格式

| 文件 | 必需列（支持常见英文别名） |
| --- | --- |
| 批次明细 | 入仓批次号、运营日、线路、行数 |
| 历史查询 | 起始运营日、截止运营日、线路（**留空 = 查全线**）、执行次数 |

- 编码：UTF-8（带 BOM 亦可），失败自动回退 GBK；日期支持 `YYYY-MM-DD / YYYY/MM/DD / YYYY.MM.DD`。
- 同 `(批次, 运营日, 线路)` 的重复行会自动合并行数并给出提示。
- 网页点“载入示例 CSV”可直接用内置样例体验（`app/static/sample_*.csv`）。

## 3. 启动方式（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

容器以非 root 用户运行，带 `/healthz` 健康检查；服务无状态、不挂载数据目录，
全程只读上传内容、不落地任何数据文件。

本地裸跑（无 Docker 时）：

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 4. 页面与接口

- `GET /`：试算网页（上传两张 CSV + 三个参数）。
  - 汇总卡片：选定文件数、总代价、全部仅按日基线代价、节省量、最少/最多文件数；
  - 各运营日布局表：逐日列出两种布局文件数、选定文件数、拆分多开文件数；
  - 查询核对区：**点开任一查询**可看该布局下命中文件数、扫描行数、代价公式，
    以及逐日明细和仅按日布局的对照值。
  - 预算不足时页面只展示“至少需要多少文件”的红色提示。
- `POST /api/analyze`：`multipart/form-data`，字段
  `batches_file`、`queries_file`、`maxRowsPerFile`、`fileBudget`、`openCostRows`，
  返回完整试算 JSON；输入错误返回 HTTP 400 与中文原因。
- `GET /healthz`：健康检查。

## 5. 自测结果

`pytest tests/ -q` → **19 passed**（`tests/test_app.py`），覆盖：

- 文件切分 ceil 规则、day_only/split 文件数（含拆分多开小文件的情形）；
- 手算样例端到端：3 个运营日、3 条查询，总代价 308000、基线 514000、选定 11 个文件；
- 背包在预算只够一个额外文件时选择节省更大的日期，预算放宽后两天都拆；
- 负收益拆分永不选中、预算不足只返回最少文件数、查询日期范围无数据时告警且代价为 0；
- CSV 解析：英文表头别名、GBK 编码、留空线路=全线、非法行数/日期/缺列报错、重复行合并；
- API：TestClient 全链路 200、预算不足 200 且 `feasible=false`、坏输入 400。

另做了真实 HTTP 冒烟（uvicorn 起服务 + curl）：`/`、静态资源、示例文件均 200；
`/api/analyze` 三种场景（可行 / 预算不足 / 坏 CSV 400）返回与单元测试一致。
背包数组 DP 与大容量稀疏 DP 两个分支用同一组数据核对结果一致。

## 7. 待办 / 已知边界

- 本机环境未安装 Docker，Compose 文件仅做了 YAML 语法与镜像内依赖版本（PyPI 200）校验，
  **未实际 `docker compose up` 跑过**，需在有 Docker 的环境再验一次。
- 背包数组 DP 容量阈值固定为 5 万；更大预算自动切稀疏字典 DP（已单测一致性），
  若日后出现超大日数 + 超大预算的极端输入，建议再做压测。
- 当前只支持“按日 / 按日+线路”两级布局；若要评估多级分区（如再按批次）或不同排序方案，
  需要扩展候选布局模型。
- 上传文件大小未做显式上限，依赖反代/网关限制；如需公网部署建议加上请求体大小限制与鉴权。
